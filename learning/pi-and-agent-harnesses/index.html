Pi, agent harnesses, and how to benchmark them

Sep 26, 2026 — Learning • Home.

TL;DR: A coding agent is a model inside a harness. Mario Zechner built Pi, a deliberately tiny harness with four tools, because bigger harnesses kept quietly changing what the model sees. And when you try to rank harnesses, you find that every benchmark score is really a model + harness pair. You can't grade the kitchen without also tasting the chef.

1. What even is a harness?

A model on its own is a brilliant chef locked in an empty room. It can tell you how to make pasta, but it can't boil water. The harness is the kitchen we build around it:

the loopsend the request, see what the model wants to do, do it, send back the result, and repeat
the toolsthe hands: read a file, write a file, run a command
the contextwhat the model sees on every turn: system prompt, tool descriptions, history

Claude Code, Codex, OpenCode, Amp, and Cursor's agent are all harnesses.

2. What was going wrong

01The kitchen keeps movingMario found that as Claude Code added features, it started behaving unpredictably. The knives kept changing drawers.
02Hidden context surgeryIn OpenCode he found context pruning that "lobotomizes" the model, and LSP errors injected after every line of an edit.
03Token bloatPlaywright MCP costs about 13.7k tokens of tool descriptions. A short README the agent reads through bash costs about 200–400.
04One size fits nobodyDifferent jobs need different harnesses. The same hammer isn't right for every construction job.
So what's the root cause?

The harness makes lots of decisions for you, invisibly, and those decisions change what the model sees. More features means more hidden text, and you can't tell why the model got confused.

3. So how would you fix it?

If the hidden stuff is the disease, what's the cure?
Have less stuff, and make every addition visible and chosen by you.

But won't a stripped-down agent be dumb?
No. Frontier models have been heavily RL-trained on coding, so they already know what a coding agent is. The chef already knows how to cook and doesn't need a 50-page manual.

So what's the smallest set of tools that still does everything?
Read, write, edit… and bash. Bash can run any program, so every other capability can be a tiny CLI script.

Enter Pi

A minimal terminal coding harness. It has a small, stable core, and every extra capability is something you explicitly add.

7. The benchmarks worth knowing

  • Terminal-Bench is the big one for terminal agents. Version 4.0 (Aug 29, 2026) has 66 hard tasks, and the official leaderboard lists the harness for each entry. You can run it yourself with Harbor: harbor run -d terminal-bench/terminal-bench@4.0.0
  • SWE-bench Verified / Pro has agents fix real GitHub issues and grades only the final patch. Be wary of vendor numbers: Opus 4.5 scored about 45.9% in Scale's standardized run and about 50–52% in a harness vendor's own comparison.
  • Harness-Bench is built specifically to compare harnesses: fixed tasks, sandbox, budget, timeout, and grader, with only the harness changing.

Before trusting any leaderboard
  • Every score is a model + harness pair. Read the harness first.
  • Scores from different versions (2.0 / 2.1 / 4.0) aren't comparable.
  • Vendor-run comparisons tend to put the vendor's own agent on top.
  • Benchmark-tuned models can crash on a harder refresh ("benchmaxxing").

8. So what should I actually do?

  1. Pick the model first.
  2. Start with its native harness (Claude Code for Claude, Codex for GPT).
  3. Reach for a minimal harness like Pi when you want control, no hidden behavior, or model-agnostic setups. I found no clean head-to-head score for Pi against the big harnesses, so don't assume it wins or loses.
  4. The benchmark that matters most is your own repo: take five tasks you've already done and run them through two harnesses.
